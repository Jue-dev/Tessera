# Portable validation

Portable validation runs project-provided build and test commands in a Linux
environment. It is supplemental and does **not** emulate Windows, the Windows
loader, unwind registration, executable memory, or native inline-hook runtime
behavior.

## Reusable Google Colab console

Open the generic
[Project Validation Console notebook](../verify/portable/Project_Validation_Console.ipynb)
in Google Colab and run its single launcher cell. The cell starts a small HTTP
server inside the active Colab runtime and prints a generated URL plus an
**Open Standalone Console** link. Open it in a separate browser tab.

The console supports portable JSON configuration profiles:

- **Load profile** imports a saved `.json` file.
- **Export profile** saves the current repository, settings, setup commands and
  tests so they can be loaded in another project/session.
- **Restore defaults** clears all project, setup and test fields.
- Profiles include the Colab Secret name only. They never export the actual
  GitHub token or other credential values.

The notebook starts with a blank configuration. To load Tessera's profile, use the GitHub profile source fields with repository `Jue-dev/Tessera`, path `verify/portable/profiles/tessera.portable-validation.json`, and ref `issue-6/unwind-lifecycle`, or import the JSON manually. The profile is
also available directly at
[`tessera.portable-validation.json`](../verify/portable/profiles/tessera.portable-validation.json).
For any project, adjust the source fields or manually import a profile. The GitHub profile fetch supports public repositories without a token and private repositories when a suitable token is available as a Colab Secret.

The GitHub token-backed repository discovery can list accessible repositories and branches, populate the repository URL/project name, and allow branch selection. Tokens are read server-side from Colab Secrets and never sent to browser JavaScript.\n\nThe interface is a responsive dark web console with:
- Repository/ref, project name, Colab Secret name, Git username, clone depth
  and timeout settings.
- Dynamically add/remove setup commands and test definitions.
- Continue-on-failure and workspace-retention options.
- Execution progress and detailed per-command logs.
- Both copy and download actions for the full text report.

The URL is generated by Colab's port proxy for the active session. It is not a
permanent or public deployment URL and stops working when the runtime ends.
No external tunnel, VPS, or external hosting is created.

## Security warning

Setup/test commands execute arbitrary shell code inside the same Colab
runtime. Colab Secrets are not isolated from code running in that runtime.
Run only trusted repositories and commands; never test untrusted pull
requests while a GitHub token is available. Review commands in any imported
profile before executing them. The runtime is ephemeral; copy or download
reports before the session ends. The report is also saved to
`/content/PROJECT_VALIDATION_REPORT.txt` during the active session.

## Tessera default profile and Linux commands

The current included profile checks the following:

1. GCC strict mock build and test:
   `bash verify/windows_mock/run_windows_mock_tests.sh`
2. Clang/libc++ strict mock:
   `EXTRA_CXXFLAGS='-stdlib=libc++' CXX=clang++ bash verify/windows_mock/run_windows_mock_tests.sh`
3. GCC AddressSanitizer + UndefinedBehaviorSanitizer:
   `EXTRA_CXXFLAGS='-fsanitize=address,undefined -fno-omit-frame-pointer' ASAN_OPTIONS='detect_leaks=1:halt_on_error=1' UBSAN_OPTIONS='halt_on_error=1:print_stacktrace=1' bash verify/windows_mock/run_windows_mock_tests.sh`

A result of `PASS` means all configured tests ran and passed.
`PARTIAL` means no test failed, but at least one test was skipped.
`FAIL` means cloning, configuration, setup, or a test failed.

## Run locally on Linux

From the repository root:

```bash
bash verify/windows_mock/run_windows_mock_tests.sh
CXX=clang++ EXTRA_CXXFLAGS='-stdlib=libc++' bash verify/windows_mock/run_windows_mock_tests.sh
EXTRA_CXXFLAGS='-fsanitize=address,undefined -fno-omit-frame-pointer' \
ASAN_OPTIONS='detect_leaks=1:halt_on_error=1' \
UBSAN_OPTIONS='halt_on_error=1:print_stacktrace=1' \
bash verify/windows_mock/run_windows_mock_tests.sh
```

## Still requires Windows/MSVC

- x86 and x64 Debug/Release CMake build + CTest
- Real native inline-hook attach, trampoline execution, detach, and rollback
- x64 unwind/function-table registration and exception behavior
- DLL unload/admission-drain lifecycle tests
- Live Microsoft Detours integration
- MSVC `/analyze`, SDK install/consumer tests, and Windows-specific fuzz smoke

These remain pending until a Windows runner produces results for the exact PR
head. Portable Linux results are not evidence for these Windows-native gates.


## GitHub Actions automation

Run the **Project Validation** workflow from the Actions tab using **Run workflow**. Select a profile JSON path; repository and ref inputs can override profile values. The workflow checks out the target repository, executes setup commands and configured tests in order, honors executable requirements, timeout and continue-on-error settings, publishes a job summary, and uploads `PROJECT_VALIDATION_REPORT.txt` as an artifact. For private target repositories, configure the repository secret `VALIDATION_GH_TOKEN` with read access; otherwise the workflow uses the repository's `GITHUB_TOKEN`.
